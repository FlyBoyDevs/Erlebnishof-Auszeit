# Schedule seasonal themes with an admin override

The public site resolves one Aktives Saisonthema in Europe/Berlin time. In **Automatisch**, Christmas runs from 1 December through 6 January and Winter from 7 January through the end of February. Spring, Summer, and Autumn each use an owner-selected start date and exactly 14 consecutive calendar days, so the inclusive end is start plus 13 days; overlapping windows are rejected. **Aus** removes both static and moving seasonal decoration. A named Manuelle Themenwahl takes precedence and remains visibly active until an editor returns the Themenmodus to Automatisch or Aus.

One discreet guest control labelled for its current action, **„Bewegung ausschalten“** or **„Bewegung einschalten“**, governs both seasonal motion and automatic hero rotation. There is no separate carousel or pause preference. Reduced-motion defaults non-essential motion to off, while turning movement off retains the static accent of the Aktives Saisonthema.

## Initial theme mapping

- **Winter:** the existing falling-snow effect.
- **Autumn:** sparse leaves falling and rotating gently.
- **Spring:** occasional blossoms or petals appearing near the screen edges.
- **Summer:** subtle golden fireflies or light motes.
- **Christmas:** individual presents, trees, candy canes, and similar shapes gently appearing and fading.

## Delivery order

The shared theme engine, global motion control, restrained static accents, and existing Winter snow effect are part of the core redesign release. Christmas, Spring, Summer, and Autumn moving variants may follow as independently tested slices; until one ships, its valid static theme remains usable. Unfinished decorative effects do not delay the legal, performance, mobile UX, carousel, or admin release gates.
